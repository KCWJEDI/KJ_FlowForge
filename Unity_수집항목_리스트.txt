====================================================================
[Unity -> Hub 수집 항목 후보 리스트]
====================================================================

작성일: 2026-08-12
목적: 허브가 유니티 에디터로부터 수집할 수 있는 항목들을 정리하고,
      각 항목의 용도/구현난이도/권장여부/발생빈도를 비교하여
      사용자가 최종 선택할 수 있도록 함.

----------------------------------------------------------------------
[읽는 법]
----------------------------------------------------------------------
- 카테고리: 수집 항목의 성격별 그룹
- 수집 항목: 허브가 유니티에서 가져올 수 있는 데이터/이벤트
- 용도: 허브가 이 데이터를 어디에 쓰는지 (노션 기록, 디스코드 알림, 깃허브 PR 본문 등)
- 구현 난이도: 낮(기본 API 한두 줄) / 중(에디터 API 조합) / 높(커스텀 핸들러/리플렉션)
- 발생 빈도: 이 항목이 허브로 전송되는 시점
  * 연결시 = 유니티가 허브에 연결될 때 1회
  * 이벤트 = 특정 동작 발생 시 (비정형)
  * 주기적 = 일정 간격 폴링/스트리밍
- 권장: ★★★(핵심, 거의 필수) / ★★(권장) / ★(선택)

[선택 가이드]
====================================================================
1. "최소한으로 빠르게 시작"을 원한다면:
   -> 1번(★★★ 전부) + 2번(★★★) + 3번(★★★만) + 5번(★★★만)
   -> 이 정도면 "유니티 빌드 -> 허브 -> 디스코드 알림 + 노션 기록"
      파이프라인이 충분히 만들어집니다.

2. "에셋 자동 커밋 자동화"까지 원한다면:
   -> 위 최소 + 4번(★★★) + 7번(★★★ 두 개)
   -> "에셋 변경 -> 자동 커밋 -> 깃허브 푸시 -> 디스코드 알림" 가능.

3. "플레이 모드 분석까지 깊게" 원한다면:
   -> 위 둘 + 3번(★★★) + 8번(★★ 세 개)
   -> 플레이 세션의 FPS/메모리/로그까지 노션에 기록 가능.

4. "전부 다"를 원한다면:
   -> 모든 ★★★ + ★★ 항목 선택. ★는 상황 보고.
   -> 트래픽/구현 부담은 커지지만 가장 풍부한 자동화 가능.
